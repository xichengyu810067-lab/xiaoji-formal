# 管理功能隔離說明

這份說明寫給邀請小吉進自己伺服器的管理員：小吉在你的伺服器裡能做什麼、不能做什麼，管理類功能放在哪裡，以及邀請時可以只給哪些權限。內容依公開程式碼整理，並有測試把關鍵數字與程式對齊（`test/managementIsolationDoc.test.js`）。

## 結論

- 在其他伺服器（不是開發者指定的伺服器）裡，小吉只提供公開指令，也就是 `/help` 列出的那些。公開程式碼沒有對成員做懲處、管理身分組、管理訊息或頻道的功能。
- 成員懲處、自動管理、身分組管理、訊息與頻道管理這類「管群」功能，屬於可選的私有擴充，不在這個公開倉庫裡。私有擴充的指令只註冊到開發者指定的伺服器，管群動作也只在那些伺服器執行；擴充裡有兩個不依伺服器範圍篩選的部分，見「擴充裡不受伺服器範圍限制的部分」。
- 擁有者專用的資料庫管理指令（吉幣資料庫、商店與賭場管理、伺服器 AI 額度）同樣在私有擴充裡，只部署到擁有者伺服器，公開倉庫不再含有它們。
- 公開功能只需要少數機器人權限（見「最小權限建議」）。不需要、也不建議授予 Administrator、封鎖成員、踢出成員、管理伺服器、管理身分組、管理訊息。

## 哪些功能不在公開程式碼

下列功能由私有擴充提供，公開程式碼裡沒有它們的指令，也沒有執行它們的程式：

- 成員懲處：封鎖、解除封鎖、踢出、禁言與逾時。
- 自動管理與新成員自動身分組。
- 身分組管理：替成員加上或移除身分組。
- 訊息與頻道的管理與記錄，例如批次清除訊息、客服單、管理紀錄頻道。

公開程式碼只留下一個「擴充介面」（見 [EXTENSION_CONTRACT.md](EXTENSION_CONTRACT.md)）。沒有載入私有擴充時，小吉照樣啟動並載入全部公開指令，這是受支援的執行方式。

工作系統有一個例外要說清楚：`/work role-sync` 是公開指令，但它只是把「同步身分組」交給擴充的介面。沒有擴充，或伺服器不在擴充宣告的範圍內，就沒有任何身分組被修改。

## 雙重保護

私有擴充的指令與動作有兩層各自獨立的限制，兩層檢查的是同一份伺服器範圍：

1. **只註冊到宣告的伺服器。** 擴充的每一組指令都宣告自己的伺服器名單，部署時只送到那些伺服器（`guildIds`）；其他伺服器的指令清單裡不會出現這些指令。擁有者專用的那一組只送到 `XIAOJI_OWNER_GUILD_ID` 指定的擁有者伺服器；這個變數沒設或格式不對時，這一組不部署到任何地方，也不會退回全域。
2. **執行時再檢查一次。** 擴充的互動守衛，以及管群相關的背景處理（自動管理、新成員處理、身分組同步、管理紀錄），都各自檢查同一份範圍；範圍外直接拒絕或略過。擴充裡並非所有作業都屬於這一類，例外見下一節。擁有者專用的資料庫管理指令在指令本身裡也會先檢查擁有者伺服器，再檢查是不是機器人擁有者。

擁有者身分不會繞過這兩層：機器人擁有者在範圍外的伺服器或私訊裡執行這些指令，同樣被拒絕（契約見 [EXTENSION_CONTRACT.md](EXTENSION_CONTRACT.md)：「Owner identity never bypasses the extension scope」）。

另外，公開核心的出口防護（所有對 Discord 的請求都要經過它）有兩條底線，擴充也不能越過：

- 非公開類的 Discord 寫入（例如對成員的處置）只有在「已通過組裝驗證的擴充」執行、且目的地伺服器在 `XIAOJI_PROTECTED_GUILD_IDS` 名單裡才會放行。
- 批量封鎖、清除成員（prune）與刪除伺服器的請求，一律不送出。

這些是程式層的限制，防的是擴充的疏忽或誤用；它們不是對惡意程式碼的隔離，那需要靠組裝驗證、程式碼審查與契約（契約中有明文說明）。

## 擴充裡不受伺服器範圍限制的部分

載入私有擴充的開發者主機上，有兩個部分不是「只在指定伺服器」運作，值得特別說明。它們不會對成員做任何處置：

1. **資料備份作業。** 這是擴充帶的一個獨立維運作業，只在載入擴充的主機上存在，並且依下列條件才會運作：
   - 預設不啟用。要有 Google 雲端硬碟的用戶端 ID、用戶端密鑰與 refresh token 三項設定都齊全才會啟動；缺任何一項，或任何選用設定的值不合法，整個作業就不啟動。測試控制模式下也不啟動。
   - 啟動後每天依設定的台北時間備份一次（預設 04:00）；小吉啟動時不會立刻備份。
   - **內容不依伺服器篩選，涵蓋所有伺服器的資料。** 包含：吉幣資料庫（帳戶是跨伺服器共用的，含所有伺服器成員的錢包、交易、購買與借款紀錄）、安全帳本與見證檔、AI 對話封存資料庫（有設定封存路徑或資料根時）、提醒與行事曆、伺服器審核與邀請者白名單紀錄、AI 對話紀錄與記憶、各伺服器的設定、投票與 AI 額度檔、客服單資料，以及資料根最上層的其他 JSON 檔。
   - 不備份：環境設定檔，檔名含 cookie、token、secret、credential 的檔案，金鑰檔，暫存檔，程式碼，以及海龜湯語料。
   - 目的地是開發者自己的 Google 雲端硬碟，只申請 `drive.file` 範圍（只看得到它自己建立的檔案與資料夾）。每次上傳後會檢查權限，只允許擁有者一筆，其他分享權限會立刻移除；只保留最近 30 份（可設定），更舊的移到垃圾桶。
   - 設定了至少 32 個字元的密語時，整包以 AES-256-GCM（金鑰由 scrypt 衍生）加密後才上傳。沒設密語時仍會備份，但不加密，程式會記一則警告。備份期間主機的暫存資料夾會短暫存在一份未加密的複本，結束後刪除。
   - 因此，如果小吉在你的伺服器裡累積了資料，這些資料可能出現在這份備份裡。隱私政策應涵蓋這一點。
2. **關注面板的按鈕。** 擴充有一個 `interactionCreate` hook，不依伺服器名單篩選，但它只處理 `customId` 帶有關注面板前綴的按鈕，而且必須對得上設定中綁定的那一個面板（伺服器、頻道與訊息）；其他所有互動它都不處理（回傳未處理）。這種按鈕只讓按下的人替自己加上或移除一個預先指定的身分組，並有冷卻時間。


## 其他伺服器看得到的指令

其他伺服器只會看到全域部署的公開指令，名單以 `/help` 為準，完整清單也列在 [COMMANDS.md](COMMANDS.md)。

公開指令裡有一些「管理員」類的指令或子指令，需要伺服器的管理權限才能用。它們只讀寫「這個伺服器自己的設定與資料」，沒有一個能對成員做懲處：

| 指令 | 需要的權限 | 作用 |
| --- | --- | --- |
| `/set-welcome` | Manage Server | 設定這個伺服器的新人歡迎頻道。 |
| `/release-announcements` | Administrator | 設定這個伺服器接收小吉版本公告的頻道。 |
| `/daily-riddle`、`/daily-discussion` | Administrator | 開關、查看與（議題）立即發布這個伺服器的每日活動。 |
| `/word-chain`、`/number-chain` | Manage Server | 停止或查看這個伺服器的接龍。 |
| `/economy`、`/coin-admin` | Administrator | 查詢這個伺服器的吉幣經濟，開關這個伺服器的吉幣系統；改動全域錢包的子指令限小吉擁有者。 |
| `/work`、`/bank`、`/shop`、`/casino-venue` 的管理子指令 | Manage Server 或 Administrator | 查看這個伺服器成員的工作、銀行、購買與菜單紀錄；少數設定限小吉擁有者。 |

要注意的資料範圍：吉幣帳戶是跨伺服器共用的，所以管理員工具會顯示「同一個伺服器成員」的吉幣餘額；成員在其他伺服器的工作主職與薪水則不會顯示給你。

## 最小權限建議

邀請小吉時請只勾下列權限。每一項都來自程式實際使用的地方（`PermissionFlagsBits` 檢查、送出的訊息內容與附件）。

| 權限 | 位元值 | 用途 |
| --- | ---: | --- |
| View Channels（檢視頻道） | 1024 | 所有在頻道裡運作的功能。 |
| Send Messages（傳送訊息） | 2048 | 新人歡迎、版本公告、每日猜謎與議題、接龍、遊戲面板、提醒、AI 對話回覆。 |
| Embed Links（嵌入連結） | 16384 | 每日猜謎、每日議題、版本公告與遊戲面板使用嵌入訊息。 |
| Attach Files（附加檔案） | 32768 | 棋盤與牌面圖片以附加檔案送出。 |
| Read Message History（讀取訊息歷史） | 65536 | 回覆訊息、接龍與數字接龍的反應、每日活動結算時讀取頻道與討論串的訊息。 |
| Add Reactions（新增反應） | 64 | 接龍與數字接龍替合格的接龍訊息加上 ✅。 |
| Create Public Threads（建立公開討論串） | 34359738368 | 每日猜謎與每日議題在公告訊息下開討論串。 |
| Send Messages in Threads（在討論串中傳送訊息） | 274877906944 | 在每日猜謎與每日議題的討論串裡發言。 |

三種常見的組合（Discord 權限整數，邀請連結的 `permissions=` 參數）：

- 全部功能：`309237763136`（上表八項）。
- 不用討論串與接龍反應：`117760`（檢視頻道、傳送訊息、嵌入連結、附加檔案、讀取訊息歷史）。
- 再加接龍反應：`117824`（上一項加 Add Reactions）。

邀請連結的 OAuth2 範圍是 `bot` 與 `applications.commands`，例如 `https://discord.com/oauth2/authorize?client_id=<機器人的應用程式 ID>&scope=bot%20applications.commands&permissions=309237763136`（`client_id` 請換成你要邀請的那個機器人）。

這些權限都可以在邀請畫面取消，或之後在伺服器設定、頻道設定裡收回。收回後的影響：

- 少了 View Channels 或 Send Messages：小吉無法在那個頻道主動發訊息。`/set-welcome` 與 `/release-announcements` 設定頻道時會檢查，缺權限會直接告訴你；每日活動與接龍啟用時也會檢查，遊戲面板在缺權限的頻道則可能送不出來。
- 少了 Embed Links：版本公告無法設定（設定時會檢查）；每日猜謎、每日議題與遊戲面板的嵌入內容不會顯示。
- 少了 Attach Files：需要圖片的遊戲面板無法附上圖片。
- 少了 Add Reactions 或 Read Message History：接龍與數字接龍無法開局；少了 Read Message History 時，回覆與每日活動結算也受影響。
- 少了 Create Public Threads 或 Send Messages in Threads：每日猜謎與每日議題無法啟用（啟用時會檢查）。

不需要，也不建議授予：Administrator、Ban Members（封鎖成員）、Kick Members（踢出成員）、Moderate Members（逾時成員）、Manage Server（管理伺服器）、Manage Roles（管理身分組）、Manage Messages（管理訊息）、Manage Channels（管理頻道）。這些權限一旦授予，會讓「程式只要有擴充就能做」變成「Discord 允許它做」，而公開功能完全用不到。

小吉還會在新加入伺服器時查詢「誰邀請了小吉」，這需要 View Audit Log（檢視稽核日誌）。沒有這項權限時程式直接略過，不影響任何功能，所以也不需要授予。

### Intents（Developer Portal 的機器人設定）

這些不是權限整數的一部分，而是機器人在 Discord Developer Portal 啟用的閘道 intent（`src/index.js`）：

- Guilds、Guild Messages：伺服器與頻道資料、接收頻道訊息。
- Guild Members（特權 intent）：新人歡迎與成員退出通知。
- Message Content（特權 intent）：讀取提及小吉的聊天、接龍與數字接龍的內容。
- Guild Voice States：公開功能不使用語音；語音狀態只交給可選的私有擴充。公開功能不需要「連線」與「說話」權限。

## 如何自己驗證

- **看 `/help`。** 在你的伺服器輸入 `/help`，列出的就是小吉在那裡提供的公開指令。
- **看「整合」。** 伺服器設定 → 整合 → 小吉，可以看到小吉在這個伺服器註冊的指令清單與每個指令的權限設定。其他伺服器只會有全域的公開指令；你也可以在這裡調整誰能使用哪個指令。
- **看稽核日誌。** 伺服器設定 → 稽核日誌會列出機器人（以及任何人）做過的封鎖、踢出、逾時與身分組變更。在沒有私有擴充的伺服器，小吉不會做這些事；若日誌裡出現，請檢查邀請時授予的權限，並回報給開發者。
- **看你授予的權限。** 伺服器設定 → 身分組 → 小吉的身分組；上面的最小權限表就是公開功能需要的全部。
- **看程式。** 公開倉庫是依白名單匯出的，不含 Git 歷史、環境檔、資料檔或私有模組路徑；開發者部署時可用 `node deploy-commands.js --audit` 比對 Discord 上實際註冊的指令（用法見 README）。

限制：這份說明描述的是程式的設計與檢查，不能證明某個正在運行的實例用的是哪一版程式。想確認時，請以第一手的畫面為準：`/help`、「整合」頁與稽核日誌。
