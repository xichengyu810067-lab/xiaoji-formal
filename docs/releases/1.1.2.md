# 小吉 1.1.2

本版強化 Discord 副作用與公開輸出的安全邊界，並補齊對使用者、維運者與私有擴充作者的說明。

- 新人歡迎、工作提醒、扣薪公告、自動離群（休眠，沒有任何程式使用）、接龍反應與 Owner 安全通知使用獨立安全帳本；首次啟動會自動建立，異常只停用受影響用途。
- 送往 Discord 的內容會移除未核准連結與非必要的 `@everyone`／身分組提及；私有擴充只在受保護伺服器且通過驗證時，才能保留明確要求的廣播提及。
- 沒有 `https://` 的網址（例如 `example.com/xxx`、`bit.ly/abc`）也會被移除，因為 Discord 可能把這種寫法顯示成連結，所以請小吉複述、投票選項或歡迎訊息裡出現都一樣；`https://` 後面緊跟表情符號、符號或看起來像英文字母的特殊字元（例如 `https://🎁.ws/x`）的網址同樣會被移除：這一段用瀏覽器自己的網址解析規則判斷，解得出主機（IP，或兩段以上、最後一段是網域結尾的名稱）就整段移除，圈起來或全形的字母與數字、中文句號 `。`、看不見的字元都會照瀏覽器的方式換算（例如 `https://ⓔⓥⓘⓛ。ⓒⓞⓜ`、`https://０x7f000001`）；瀏覽器因為看不見的字元而拒收的，去掉它們再讀一次。瀏覽器解不出主機的，只是在說明 `https://` 的文字（例如「網址要以https://開頭」「要用https://開頭，版本v1.1.2以後都支援」），以及好幾句話連在一起、最後一句不是網域結尾的段落（例如「請用https://開頭的網址。謝謝！」），不受影響。最後一段剛好是英文字或網域名稱的（例如「以https://開頭。OK」），與 `https://領獎。台灣` 無法區分，會整段移除。已核准的連結包在粗體、底線或刪除線裡（`**https://discord.gg/TqkCx9kYmk**`）照樣保留。版本號（`v1.1.2`）與電子郵件不受影響；檔名只有結尾不在連結結尾清單內的（`README.md`、`main.py`、`data.json`）不受影響，結尾剛好也是網域結尾的（例如 `requirements.in`、`model.pt`、`book.mobi`、`logo.ai`）仍會被改寫。名稱前面整段都是中文、日文或韓文字（例如 `我今天很累.Today`、`謝謝.Life`）時，要帶連接埠、路徑、查詢或片段（`領獎.com/x`）才算網址。上傳的文字檔只改寫有 `https://` 的網址與邀請連結，不改沒有 `https://` 的名稱，所以設定匯出檔裡的 `announcement.channel.id` 這類鍵名不會被動到。轉傳訊息（forward）的請求一律不送出，因為轉傳的內容是 Discord 在送出後才帶入的，無法先檢查。AI 回覆遇到這種網址時，照一般連結的方式清理並記錄，不私訊擁有者。
- 輸出設有分用途限流。超過上限的可重試工作會延後，不會先被寫成已送出；歡迎與 Owner 通知等一次性事件則不補送。
- 大量成員同時加入時，新人歡迎改用小吉已同步的頻道資料挑選頻道，不再每加入一人就向 Discord 查詢一次；只有資料確實不足時才查詢，同時加入的成員共用同一次結果，查過之後會隔一段時間（最長一分鐘）才再查。
- 私有擴充在受保護伺服器裡的管理操作（成員懲處、身分組、刪訊息、建立或刪除頻道等）改用較寬鬆但仍有上限的額度；私有指令回覆自己的互動時，可以附上 1 個 1 MiB 以內的文字檔（例如設定匯出）。擁有者用私有指令讓小吉離開其他伺服器時，會先確認發起者就是擁有者，受保護伺服器則永遠不會離開。詳細數字見 README 的「出口防護」。
- 小吉不再審核伺服器：加入任何伺服器都可以直接使用公開功能與工作提醒私訊，不需要批准，也沒有拒絕名單，小吉也不會自動離開任何伺服器；加入新伺服器只通知擁有者。
- AI 對話新增防洗頻，擁有者與所有伺服器一體適用：沒有文字、整句只是同一個字或同一小段一直重複、10 分鐘內第 3 次說同樣的話、短時間連發（每人每個伺服器 60 秒 5 次、10 分鐘 20 次），或同一頻道太多人同時找小吉（60 秒合計 10 次）的訊息，會在送給 AI 之前擋下，不消耗 AI 額度，也不寫入對話紀錄。10 分鐘內被擋 3 次會暫停 AI 對話 10 分鐘，之後再犯依序延長為 30 分鐘、2 小時。被擋時小吉最多回一則簡短說明，不會 @ 本人。
- 只 @小吉 或只叫「小吉」（後面沒有文字，或只有標點、表情符號）時，小吉回「我在，有什麼事嗎？」（每人 10 分鐘一次），不呼叫 AI，也不算違規；直接回覆小吉、內容只有標點或表情符號時不回覆，也不算違規。
- 海龜湯的提問也有防洗頻：無意義的提問、10 分鐘內第 3 次問相同的問題，或同一人 60 秒超過 6 次、10 分鐘超過 40 次，會只回給你自己看的說明，不判題、棋局保留。
- 小吉擁有者設定的伺服器 AI 額度開始生效（預設不限）：聊天每真的呼叫一次 AI 才扣 1，被擋下或固定回覆不扣；用完時小吉會請你晚點再試。扣用是本版新接上的，用量不會自動歸零；部署前請先由擁有者確認各伺服器的 limit 與 used。
- AI 回覆裡的連結或提及被清理、AI 呼叫因忙碌、太頻繁、重複內容或逾時被擋下時，不再私訊擁有者，也不占用擁有者通知的額度。被拒答的請求，同一伺服器的同一人每天最多私訊一次；這個上限只擋同一個人重複，很多不同成員各被拒答一次時，每一則仍會用掉擁有者通知的共用預算（每分鐘 1 則、每小時 6 則、每天 24 則）。所以 Owner 的安全通知不會被上述例行事件或單一成員的重複拒答擠掉。新伺服器加入、成員退出與恢復營運各是獨立事件，文字固定、不經過 AI 對話，並各有自己的預算（成員退出每分鐘 2 則、每小時 12 則、每天 48 則；新伺服器加入每分鐘 1 則、每小時 6 則、每天 24 則；恢復營運每分鐘 1 則、每小時 2 則、每天 4 則），不占用也不被上面的共用預算占用。三種事件的來源都已接上：加入新伺服器、成員退出與停運後恢復營運，都以固定文字的獨立通知送出。
- 安全帳本支援保留期壓縮與容量保護；維運時以 `npm run safety:ledger -- status` 先做唯讀檢查，只有 status 顯示確認碼時才依指示執行 reinit。
- 小吉連續啟動失敗 3 次後（啟動後登入 Discord 並穩定運作滿 10 分鐘才算成功），下一次啟動起暫停所有 Owner 私訊，直到某次啟動成功為止，避免自動重新啟動時一直私訊；暫停期間擋下的通知不補送。用 `npm run safety:ledger -- status` 可查看次數，停止小吉後執行 `npm run safety:ledger -- reset-start-failures --bot-stopped` 可手動歸零。
- 開啟 Owner 私訊頻道連續失敗 3 次後，到下次啟動前不再嘗試，並在 log 記一行說明。開啟的請求若已送到 Discord 卻失敗，之後的 Owner 通知都送不出去：每次啟動會在 log 記一行，`npm run safety:ledger -- status` 也會標示，依 README 的步驟停機後重建 Owner 帳本即可恢復。

完整的資料位置、備份、異常處理與回復步驟請見 README 的「受保護的副作用與安全帳本」。

## 賭場餐廳與工作修正

- 廚師或調酒師超過 24 小時沒做完、由小吉接手做好時，服務生不再被記成「逾期未送達」：小費照樣全額退還顧客，服務生的任務會註明服務生不算逾期。餐點準時做好、服務生自己 24 小時內沒送達的情況，仍記為服務生逾期並退還小費。
- 服務生任務的結案原因不再因為兩個逾期檢查哪個先執行而不同；同樣的情況一定得到同樣的結果。
- 取消訂單最後一個待處理品項時，訂單記為已取消：小費退還顧客，服務生任務記為「已取消」並寫明是訂單取消，不再被當成服務生逾期，也不再記成由系統送達。同一筆小費只會退還一次。
- 取消品項時若原本的待辦無法核對，錯誤訊息改為「暫停取消」，不再出現改派的字樣。
- 改派或取消而結束的工作任務一律記為「已取消」，`/work` 查詢紀錄的「已取消」篩選可以找到它們；以前用另一種拼法存下的紀錄也會一起列出，不需要搬移資料。
- 主職廚師或調酒師完成餐點的管理紀錄，會記下所屬的主職週期。
- 已取消、已逾期或由小吉接手完成的工作任務不能再用 `/work edit` 修改或用 `/work delete` 刪除，避免已結束的任務被改回待審核，或結束的紀錄被蓋掉；扣薪紀錄本來就不受刪除影響。
- 服務生、廚師與調酒師的場館任務由系統管理，不能用 `/work edit` 或 `/work delete` 修改或刪除，也不能用 `/work review` 審核；提交、回報或新增待辦時也不能自己填場館任務類型。避免週期發薪因場館紀錄對不上而暫停。切換前留下的舊場館待辦，也只能透過原訂單流程完成。
- 已取消、已逾期或由小吉接手完成的工作任務不能再被審核，避免系統結案的紀錄被改成核准而算進薪資。
- `/work cancel` 改為清楚說明「目前不開放辭職」：已開始的工作會在選定的天數期滿時自動結算薪水並結束。指令說明、`/help` 與指令清單也同步寫明。
- 另外修正兩個目前資料庫不會走到的舊路徑：舊版資料結構下指定服務生時的查核錯誤，以及舊工作逾期處理在指定時間時仍寫入當下時間的問題。

## 指令回覆修正

- `/bank` 的錯誤提示全部改成中文，例如定存 ID 不存在時回「找不到這筆定存，請用 /bank fixed-list 確認定存 ID。」；活存不足時也會列出目前活存與需要金額。個人小遊戲裡方塊超出棋盤、選了同一格時，提示也改成中文。
- `/calendar list` 的回覆會寫出查詢範圍（預設未來 30 天）；沒有事件時回「未來 30 天內沒有行事曆事件。可用 days 選項查更遠的日期（最多 365 天）。」，不再出現中英夾雜的句子。
- `/economy audit` 與 `/coin-admin history` 的交易類型、定存與工作狀態、利率名稱改用中文顯示（例如「每日簽到」「已到期，可領取」「30 天定存」），不再出現系統內部的英文代碼。
- `/coin-admin history` 沒填 user 時，改為說明要用 user 指定成員（全伺服器的最近交易請用 `/economy audit`，活動歷史對帳請填 campaign-id），不再誤報「活動資料不完整」；填了 page、reason、confirm 等活動對帳用的選項卻沒填 campaign-id 時，會列出這些選項並說明需要搭配 campaign-id，不再默默忽略。
- `/weather` 與 AI 天氣查詢：有設定中央氣象署金鑰時，用英文輸入的臺灣地名（例如 Hsinchu、Taipei City），以及舊版存下的英文預設城市，都改查中央氣象署並顯示中文地名，含風向、降雨機率與「中央氣象署預報」頁尾，不會再退回 OpenWeather。沒有中央氣象署金鑰時照舊查 OpenWeather；海外城市也照舊查 OpenWeather，回覆頁尾會標明「OpenWeather 即時天氣」或「OpenWeather 預報」。
- AI 天氣查詢改成從整句話找地點與時間，語助詞不再被當成地名：「明天高雄會下雨嗎」「這週末台中天氣」「桃園這禮拜天氣」「台北今天要帶傘嗎」都能正確回答；只問「今天會下雨嗎」沒有說地點時，伺服器有設預設城市就查預設城市，沒有就請對方補上地名。也能讀中文的海外城市名（例如東京、大阪、紐約）與英文句子（例如 weather in Tokyo、Taipei weather tomorrow）。「下雨天心情不好」「台北好玩嗎」這類閒聊不會被當成天氣問題；「幾度」「會冷」「會熱」要有地點，或同時有疑問與時間（例如「今天冷不冷」），才算天氣問題，所以「冷氣要開幾度」「發燒幾度要看醫生」這類句子交給一般對話；「冷嗎」「熱嗎」「預報」也要有地點才算（「你今天冷嗎」「股市預報」不是天氣問題，「台北明天預報」是），「你的車有雨刷嗎」也不會被當成下雨。行政區寫在別的縣市底下（例如「台北樹林區」）時，小吉會回「找不到這個行政區」，不再改答整個縣市的天氣。「週末」改為回傳這個週六與週日的預報（已過的那天不列；預報沒有涵蓋時回「該日期目前沒有可用的預報。」），不再被當成今天或明天；「下週末」改為一週預報。問昨天、上週、去年等過去的日子，或下個月、明年等太遠的日子，小吉會說明只能查今天起約一週內的預報，不再用今天的天氣回答。簡體字（例如「天气」「吗」）也讀得懂。`/weather` 的 city 選項說明改成能直接成功的例子，`/weather city:東京` 這類中文海外城市名也可用。
- `/bank` 建立或查看定存時，狀態與扣款來源改用中文（例如「存放中」「錢包」）；利率清單與利率調整紀錄的利率名稱也改用中文（例如「活存」「30 天定存」）。
- `/economy audit` 與 `/coin-admin history` 的交易原因與利率調整原因改用中文：新紀錄直接寫入中文（例如「存入活存」「活存利息（日期）」「活動利率到期，自動恢復」），舊版留下的英文原因在顯示時對照成同樣的中文；不認得的原因照原樣顯示。
- `/calendar list` 的回覆一定在一則訊息內：內容太長時會縮短過長的說明，仍放不下的事件改為註明「另有 N 筆事件未顯示」；超過 10 筆時也會註明。
- 其他把很多筆資料接成一則的清單也一樣不會因為太長而整則失敗：`/shop list`、`/shop purchases`、`/shop purchases-user`、`/shop purchases-all`、`/luxury list`、`/luxury history`、`/remind list`、`/bank balance-all`、`/bank fixed-all`、`/bank rate-history`、`/economy audit`、`/economy user`、`/coin-admin history`、`/work` 的狀態、提交、任務、發薪與扣薪查詢、`/pawn active`、`/pawn history`、`/inventory`、`/exchange history`、`/casino history`、`/duel-tower weapons`、`/duel-tower history`、`/casino-venue menu`、`/casino-venue history`，以及 `/casino-venue` 的製作步驟。內容放得下時回覆和以前完全一樣；太長時，名稱、說明與原因會一起縮短（用「…」標示），仍放不下的筆數改為註明「另有 N 筆未顯示」並說明怎麼看其餘。以前這些情況會只回「系統暫時無法處理吉幣資料」之類的失敗訊息。
- `/remind list` 在 Discord 拒收回覆時，不再誤報「提醒資料目前無法安全讀寫」；這句只用於提醒資料真的讀寫失敗。
- 擁有者專用的吉幣資料庫狀態只顯示資料庫的檔案名稱，不再顯示完整路徑（路徑會帶出主機的資料夾與使用者名稱）；完整路徑請在主機上查看 `COIN_DB_PATH` 設定。
- `/casino` 與擁有者專用的賭場債務查詢的借款狀態改用中文（「借款中」「已還清」）；沒有借款時回「目前沒有未還清的賭場借款。」。
- `/work status`、`status-user`、`status-all` 的全域主職資訊不再出現「由私有擴充核對」：有管理功能負責同步主職身分組時顯示「角色同步：由管理功能核對」，沒有時不顯示這一行。
- `/work role-sync` 被身分組變更上限或排隊上限中途擋下時，回覆標題改為「工作身分組同步已暫停，尚未全部完成」，不再寫成「同步完成」；原因仍排在第一則提醒，稍後再執行一次即可繼續。
- 個人遊戲（俄羅斯方塊、數字配對、數獨）開局後可以用 `/board stop` 提前結束：會結束你在這個頻道所有進行中的個人遊戲，不會動到別人的或其他頻道的；公開的遊戲面板改成「已提前結束，沒有獎勵」並拿掉按鈕，提前結束不發獎勵。如果你同時是這個頻道公開桌遊或海龜湯的房主，`/board stop` 仍先處理那一局，再用一次才會結束個人遊戲。
- `/casino-venue order` 選到機器人（例如小吉自己）當服務生、廚師或調酒師時，會直接回「服務生不能是機器人，請改選真人成員。」（依選項換成廚師或調酒師），不再回「目前無法核實場館工作人員…請稍後再試」讓人誤以為稍後可以成功；管理員用 `reassign`、`reassign-waiter` 指派給機器人時也一樣。Discord 的成員選單本身會列出機器人，無法由小吉過濾，所以選到機器人時由小吉拒絕並說明。
- 每日猜謎與每日議題的公開貼文，頁尾不再顯示內部的發布編號，改成「每日猜謎・日期」「每日猜謎解答・日期」「每日議題・日期」。小吉仍能在重啟後認出已經送出的貼文而不重複發布，升級前已送出的貼文也認得出來。

## 查詢範圍、資源上限與結算修正

- 看別人的餘額、背包與定存時，不再替對方在本群建立紀錄；管理員的這些查詢限本群成員，背包審查只列本群玩家，指派工作任務也限本群成員。他群選擇的主職，在本群只顯示「其他伺服器」。
- 行事曆每人最多保留 100 筆未結束的事件，並自動清除 30 天前的舊事件與刪除紀錄。投票改為安全寫檔，每個伺服器最多 20 場進行中，結束 7 天後清除，按鈕也會核對所屬的訊息與伺服器。提醒的已送達與失敗紀錄保留 7 天，每人最多 50 筆。另外修正棋盤控制項的查表、海龜湯猜答案的字數上限，以及擁有者專用額度管理的伺服器 ID 檢查。
