# 小吉 1.3.3

這一版主要整理小吉的內部架構，讓之後的新功能更好加、更不容易出錯。吉幣資料庫換成 Node 內建的 SQLite，交易變快，資料越多也不會越慢。

## 吉幣與資料庫

- 吉幣資料庫改用 Node 內建的 SQLite（`node:sqlite`），以 WAL 模式開啟。以前每筆交易都要把整個資料庫重寫一次，資料越多越慢；現在只寫改到的部分，速度不再隨資料量變慢。
- 每筆交易在確認時就寫進磁碟；升級資料表結構前會先自動備份，升級失敗會自動還原。
- 資料表結構不變，仍是第 24 版。

## 指令

- `/coin-admin history`（查詢交易或執行活動歷史對帳）改為只有 Owner 可以使用；`enable`、`disable` 仍由伺服器管理員使用。
- `/coin-admin` 會拒絕格式不正確的使用者 ID。
- `/bank balance-all`、`fixed-all`、`rate-history` 的筆數上限輸入小數時，會自動取整數；`/bank fixed-create` 只接受錢包或銀行作為來源。
- 21 點的牌局綁定在開局的頻道與面板訊息上，不能從別處操作。

## 狀態頁

- 1.1.0 以前的網頁遊戲伺服器已完全移除。它留在資料庫裡的三筆舊「維護中」紀錄（俄羅斯方塊、數字配對、數獨）會在小吉啟動時自動清除，狀態頁不會再被它們影響。

## 對話與安全

- 一般聊天和海龜湯的裁判共用同一套 AI 服務選擇規則，兩邊的行為一致。
- 補強不洩漏內部資訊的規則：識別名稱裡夾帶的服務商名稱、自我介紹之後追問開發計畫、一般的中文操作問題等情況，都有對應的處理與測試。
- 對話與賭場的暫存資料有數量上限，並每分鐘清除過期的項目，不會無限增加。

## 其他

- 內部架構重整：舊的轉接檔全部移除，各功能的程式搬到所屬系統的目錄，社群接龍與每日活動的設定改走同一個功能設定介面。這些改動不影響使用方式。
- 移除不再使用的 `sql.js` 套件。
- 狀態頁的 Cloudflare Worker 改為自己宣告需要的套件。

## 升級

- 隱私權政策與服務條款沿用 1.3.1，`XIAOJI_ARCHIVE_POLICY_VERSION` 維持 `1.3.1`。
- **第一次部署這一版：**先正常停止舊版小吉（不要強制終止），把吉幣資料庫、`safety/` 與 `safety-witness/` 一起備份，再部署並啟動。第一次啟動會把吉幣資料庫切換成 WAL 模式，資料不動；執行期間資料庫旁邊會有 `xiaoji.sqlite-wal`，正常停止時會併回主檔。詳細步驟見 `docs/OPERATIONS.md` 的「第一次部署這個版本與退回舊版」。
- **退回 1.3.2 以前的版本：**正常停止小吉後，先執行 `node scripts/coin-db-checkpoint.js` 把資料庫改回舊格式，再部署舊版。
- `.env` 裡的 `GAME_SERVER_ENABLED`、`GAME_SERVER_HOST`、`GAME_SERVER_PORT`、`GAME_CORS_ORIGINS`、`GAME_SESSION_SECRET`（以及 `GAME_PREVIEW_PORT`，如果有設定）已經沒有作用，可以刪除。
- `/coin-admin` 的指令說明有變，部署後要重新部署指令。
- 狀態頁的 Cloudflare Worker 新增了自己的 `package.json`：Worker 透過 Workers Builds 連接 GitHub 自動部署時，請確認 Root directory 設定為 `cloudflare/status-worker`。
