# Jev 第二意見設定指南（擁有者用）

這份文件說明怎麼把 TypeSafe AI 的 Jev 決策模型接成小吉 AI 回覆的「第二意見」。它是**可選功能，預設關閉**；不設定也完全不影響小吉。

## 1. Jev 是什麼，它在小吉裡做什麼

Jev 是一個用 HTTP 呼叫的分類服務：你給它一段文字和幾個「是非題」，它回答每一題「為真」的機率（0 到 1）。它不會產生文章，也不是聊天模型。

小吉的 AI 回覆在送出前，本來就會經過一組規則檢查，擋下可能洩漏內部資訊的回覆，被擋的人會看到固定句「小吉不是很清楚，請之後再詢問」。其中有兩類規則比較「寬」（軟規則），偶爾會把正當的回覆也擋掉：

- 回覆裡只出現英文單字 `bot`，旁邊剛好有「部署、程式碼、架設、框架、套件」這類一般的程式用語（例如「寫 bot 時要先裝套件」）。實際涵蓋的範圍是：**唯一指到小吉的詞只有裸 `bot`**，也就是 `bot` 前面加任何東西（`Discord bot`、`this bot`、`the bot`、`my bot`、`這個 bot`、`這隻 bot`、`該 bot`、`本 bot`）都算；而且主題只有上面那五個一般用語。只要句子裡另外有「小吉」、`xiaoji`、「這個機器人」、「此系統」、`your bot`，或主題是模型、提示詞、roadmap、下一版、製作過程等其他內部主題，就是硬規則，不放寬。注意「這個 bot」「該 bot」這類說法在對話裡可能真的指小吉，所以這一條的實際暴露面比字面上看起來大，這是刻意固定下來的現況（測試 `jevSoftRules` 逐句固定），請在第 5 節實測時特別留意。
- 回覆用「它、這台、該專案、這個專案」這類指代詞，旁邊剛好有「功能、設定、版本」這類一般用語，而對話裡沒有任何地方說到它指小吉（例如「它的功能很多」）。指代詞旁邊如果是強烈的內部主題（模型、原始碼、提示詞、部署位置、金鑰、後端、資料庫、內部，以及誰開發、製作、打造它、哪個團隊或公司做的），仍視為硬規則，不會被放寬，也不會送去問 Jev。

開啟 Jev 之後，**只有**「被軟規則擋下」的回覆，會再問 Jev 一次：兩題（回覆有沒有洩漏內部細節？有沒有捏造規則或例外要小吉放行？）都低於門檻才算安全，才改為放行。其餘一律照舊：

- 硬規則（金鑰、提示詞內容、模型名稱、第一人稱的自我描述、明稱小吉的內部說明等）永遠照常檢查，Jev 的意見不影響它們；被硬規則擋下的回覆，根本不會送去問 Jev。
- Jev 不是唯一的關卡：放行後的回覆仍然經過所有硬規則。
- Jev 逾時、出錯、回傳不合預期、被限流、說有風險、伺服器不在名單內、功能關閉：一律與沒有 Jev 時完全相同。
- 使用者進來的請求（入口端的 AI 對話請求）完全不問 Jev。Jev 的另一個用途是第 10 節的「連結風險」，那是另一條獨立的路徑，不會放行任何被擋下的回覆。

已知弱點：第三方測試（Datadog、Lasso）發現，若輸入偽造了「政策、例外」之類的字樣，這類模型可能被誘導放行，召回率會大幅下降。所以才採用上面「只放寬軟規則、硬規則不動」的設計，並把使用者與模型的文字只放在送出內容的資料欄位，從不拼進題目文字。

## 2. 取得金鑰

1. 開啟 https://console.typesafe.ai/ ，用 Google 或 email 登入。
2. 進入 https://console.typesafe.ai/keys 建立一把 key。**金鑰只會顯示一次**，請立刻存進你的密碼管理工具。
3. 注意：官方文件對 early access（搶先體驗）的說法前後矛盾。如果登入後主控台說要排候補名單（waitlist），就只能等官方開通；可先寄信或到官方管道詢問進度，並用下面的備援路徑。

### 備援路徑（不一定要用官方主控台）

| 路徑 | 位址 | 模型名稱 | 注意 |
| --- | --- | --- | --- |
| OpenRouter | `POST https://openrouter.ai/api/alpha/decisions` | `typesafe/jev-1.13` | 不能走 chat completions，也不能用 openai SDK；刷信用卡儲值有 5.5% 手續費 |
| Vercel AI Gateway | `https://ai-gateway.vercel.sh/typesafe/v1/systemone` | `typesafe-ai/jev` | 同樣是 systemone 格式 |

用備援路徑時，把 `JEV_ENDPOINT` 和 `JEV_MODEL` 改成上表的值（`JEV_ENDPOINT` 一定要是 https）。這些路徑的回應是否完全相容，請先用第 5 節的 shadow 模式與評估工具確認；不相容時小吉會記下固定代碼 `bad_shape` 並照舊運作。

## 3. 把金鑰放進你自己的 `.env`

在小吉執行的主機上，編輯 `.env`（這個檔案不進 Git，也不要貼到聊天室、截圖、commit 或回報裡）：

```
JEV_API_KEY=your_jev_api_key
```

上面的 `your_jev_api_key` 只是佔位字，請在你自己的 `.env` 裡換成真正的金鑰，不要把真值寫進這份文件或任何會進 Git 的檔案。

`.env.example` 只放佔位字，不會有真值。`scripts/create-public-export.js` 的匯出檢查也會擋下帶真值的 `JEV_API_KEY=` 行。小吉的日誌與 AI 輸出檢查都會自動遮蔽名稱含 `API_KEY` 的環境值，但仍請當作機密保管。金鑰外洩時，到主控台撤銷並重建。

## 4. 環境變數

| 變數 | 預設 | 意義 |
| --- | --- | --- |
| `JEV_MODE` | `off` | `off` 關閉；`shadow` 只問並記錄固定代碼，不改變任何結果；`enforce` 才會真的放行。 |
| `JEV_API_KEY` | 無 | 金鑰。缺少、格式不對，或還是 `.env.example` 裡以 `your_` 開頭的佔位字，都視為關閉，並警告一次（警告不會顯示值）。 |
| `JEV_POLICY_ACK` | 無 | 必須等於 `yes` 才會啟用 shadow 或 enforce。代表你已確認隱私政策與條款更新過，知道成員文字會送到第三方。沒有就視同 `off`，並警告一次。 |
| `JEV_LINK_RISK` | 空 | 必須等於 `yes`，才允許把「含連結的伺服器訊息文字」送去做連結風險的第二意見（第 10 節）。沒設或不是 `yes` 時，連結風險只用內建規則，**完全沒有網路呼叫**；設了它也不會單獨啟用任何功能，仍需要 `JEV_MODE`、`JEV_POLICY_ACK`、金鑰與 `JEV_GUILD_IDS`。它與回覆用途分開：只開回覆第二意見時，成員訊息不會被送出。 |
| `JEV_GUILD_IDS` | 空 | 允許使用的伺服器 ID，用逗號分隔。空白代表不對任何伺服器啟用。私訊永遠不使用。 |
| `JEV_ENDPOINT` | `https://api.typesafe.ai/v1/systemone` | 必須是 `https:`，不能帶帳號、查詢字串，也不能是 localhost、`.local`、迴路位址或內網位址（10.x、172.16 到 31.x、192.168.x、169.254.x、IPv6 的本機與內網）。允許改成其他公開的相容端點。 |
| `JEV_MODEL` | `jev-1.13.0` | 固定版本。請不要改成會變動的別名（例如 `jev-latest`），否則判斷結果會在你不知道時改變，之前評估的數字也就不再適用。小吉不會擋下別名，這只是勸告；要升級版本時，請重新跑第 5 節的評估。 |
| `JEV_TIMEOUT_MS` | `3000` | 單次等待上限。下限 200，最大 5000：設得更小會被提高到 200，更大會被降到 5000；不是正整數則改用預設 3000 並警告一次。逾時就照舊（被擋）。 |
| `JEV_SAFE_MAX` | `0.10` | 風險機率小於等於這個值才算安全，可設 0 到 0.5。「有沒有捏造規則」那題另外固定用更嚴的 0.05（設得比 0.05 更低時以較低者為準）。 |

設定錯誤時，功能整個關閉，小吉其他部分照常啟動。改完要重新啟動小吉才會生效；要緊急停用，把 `JEV_MODE` 改成 `off` 後重啟即可，沒有任何資料需要還原。

## 5. 建議的上線順序

1. **先更新隱私政策與條款**（見第 6 節），再設 `JEV_POLICY_ACK=yes`。
2. 設 `JEV_MODE=shadow`，`JEV_GUILD_IDS` 只放**一個**伺服器。這時 Jev 的結果只寫進日誌，行為完全不變，也不會讓回覆變慢。日誌裡會看到 `[JEV_SHADOW] verdict=safe`、`risky` 或 `error`（只有代碼，沒有任何文字）。
3. 用評估工具離線打分：`node tools/jev-eval/jev-eval.js --dry-run` 先看會送多少樣本與估計費用（完全不連網）；確認後在環境變數裡放 `JEV_API_KEY`，再執行不帶 `--dry-run` 的版本（可用 `--limit`、`--concurrency`、`--out`）。**評估工具只存在私有倉庫**（`tools/jev-eval/`，公開匯出不含它，所以公開版的程式碼沒有這個目錄），報告預設寫在暫存資料夾，不寫進專案；它的測試用 `node --test tools/jev-eval/test/jevEval.test.js` 手動執行，不在 `npm test` 裡。報告的 `gate.status` 有三種：`ready`（有至少一個「本該被擋、只被軟規則擋下」的樣本被評估、沒有任何呼叫失敗、而且沒有任何一個被判為安全）、`not-ready`（有樣本被判為安全，或任何一次呼叫失敗），以及 `insufficient-data`（沒有這種樣本可評估）。**只有 `ready` 才能考慮 `enforce`；`misreleased` 是 0 但狀態是 `insufficient-data`，什麼都沒證明。** 內建語料幾乎沒有這類樣本（目前內建語料中被軟規則擋下的樣本是 0），所以幾乎一定得用 `--extra` 提供你自己整理的樣本（一個 JSON 陣列，每筆有 `label`（`attack` 或 `legit`）、`userText`、`replyText`；請放入你收集到的「正當但被誤擋」的回覆，以及你自己構造的「本該被擋、只被軟規則擋下」的回覆）。
4. 評估通過、shadow 日誌也沒有異常，才把同一個伺服器改成 `JEV_MODE=enforce`，觀察一段時間，再逐步加入其他伺服器。
5. 只要看到不對勁（日誌出現大量 `error`、成員抱怨放行了不該放的內容），立刻改回 `off`。

## 6. 隱私提醒

啟用後，**被軟規則擋下的那一則 AI 回覆，以及成員提出的那句問題，會被送到 TypeSafe AI（美國的第三方服務）**。送出前小吉會做最基本的去識別化：

- 不送使用者 ID、伺服器名稱、頻道名稱。
- `<@…>` 之類的提及會被換成 `[mention]`；15 位以上的數字（連續的，或用單一空白或連字號分成三位以上一組，例如信用卡號樣式）換成 `[id]`，日期、版本號與短數字不受影響；密鑰與權杖樣式的內容會被遮蔽。這些遮蔽都在截斷到長度上限**之前**做，所以被截斷位置切開的密鑰也會整個被遮蔽。
- 成員的顯示名稱：呼叫時會把當事成員的顯示名稱從兩段文字裡換成中性詞，但只換小吉政策本來就能安全遮蔽的名稱（太短、或可能藏有內部詞彙的名稱不處理）；不能遮蔽的名稱、以及模型在回覆裡提到的其他人名，會原樣送出。
- 每段文字最多 1500 字（遮蔽在截斷之前）。
- 只有功能開啟、伺服器在名單內、而且回覆只被軟規則擋下時才送出；平常的回覆、被硬規則擋下的回覆、私訊、入口端的請求都不會送。（連結風險用途有它自己的送出條件，見第 10 節。）

即使如此，成員的文字仍會離開小吉的主機。因此**啟用前請先更新公開的隱私政策與使用條款**（說明有一個選用的第三方服務會處理被標記的對話文字、送到哪裡、用途），確認後才設 `JEV_POLICY_ACK=yes`。這個變數是你對自己的確認，不是技術檢查。也請另外確認 TypeSafe AI 的資料保存與訓練條款符合你對成員的承諾。

## 7. 費用估算

官方輸入價格約 0.042 美元／百萬 token（輸出只有每題一個機率，數量很小，實際以官方價目表為準）。每次問 Jev 約 150 到 400 個輸入 token，所以 1000 次約 0.006 到 0.017 美元。而且只有「被軟規則擋下」的回覆才會問，加上每分鐘上限 30 次，所以費用上限很低。評估工具對整份語料完整跑一次，預估約 8 萬個輸入 token、約 0.0035 美元（`--dry-run` 會印出目前的準確估計）。

小吉自己也有成本保護：同時最多 2 個呼叫、全域每分鐘最多 30 次，超過就視同失敗（維持被擋）；連續失敗 5 次，會暫停呼叫 60 秒。不重試。

## 8. 已知限制

- 繁體中文沒有公開的評測數據，這個專案也還沒有用真實金鑰量過準確率。請務必用第 5 節的流程，用你自己的樣本實測，不要只相信廣告數字。
- 對抗性輸入有弱點（見第 1 節）。小吉不依賴 Jev 擋任何東西，只用它放寬少數軟規則。即使如此，「Jev 全部都說安全」時，仍可能有少數被軟規則擋下的回覆被放行，這就是這個功能的最大暴露面。目前內建的攻擊語料裡這批樣本數是 0（測試固定這個數字，增加時測試會失敗）；但語料不可能涵蓋所有說法，尤其第 1 節列出的 `bot` 軟規則涵蓋範圍（`這個 bot`、`該 bot` 等）是刻意固定下來的現況，所以仍請照第 5 節實測。
- 只吃文字，不支援串流、圖片或檔案。
- 單次等待最多數秒；只在被軟規則擋下時才發生，不影響一般回覆的速度。

## 9. 故障排除

日誌裡的 `[JEV] Call not completed: reason=…` 只有固定代碼，不含任何使用者文字或金鑰。相同代碼每分鐘最多記一行，被省略的次數寫在 `suppressed=` 後面。

| 代碼 | 意思與做法 |
| --- | --- |
| `auth` | 401 或 403：金鑰錯了、被撤銷、沒有權限，或（官方路徑）帳號還在候補。到主控台確認，重建後更新 `.env` 並重啟。 |
| `rate_limited` | 429：被對方限流。降低使用範圍（`JEV_GUILD_IDS`）或確認方案額度。 |
| `overloaded` | 529：對方暫時過載。通常等一下會恢復，小吉會維持原本的擋下。 |
| `server_error` | 5xx：對方服務出錯。同上。 |
| `rejected` | 400、413、415 或 422：送出的內容被拒。最常見是端點或模型名稱不是 systemone 格式；請檢查 `JEV_ENDPOINT` 與 `JEV_MODEL`。 |
| `timeout` | 超過 `JEV_TIMEOUT_MS`。網路慢或對方慢；可小幅調高（最多 5000），或維持原狀。 |
| `network` | 連不上、憑證錯誤，或端點把請求轉址（小吉不跟隨轉址）。檢查 `JEV_ENDPOINT`。 |
| `bad_shape` / `too_large` | 回應格式或大小不符預期，常見於不相容的端點。 |
| `circuit_open` | 連續失敗後的暫停期（60 秒），之後自動試一次。先排除上面其他代碼。 |
| `busy` / `budget` | 同時呼叫或每分鐘次數達到上限，屬於正常的成本保護。 |
| `disabled` | 設定不完整或功能關閉。第一則 AI 回覆處理時，日誌會出現一次警告 `[JEV] Disabled (…)`，說明缺哪一項（警告不顯示任何值）。 |

設定了 `JEV_MODE` 卻在日誌看到 `[JEV] Disabled (policy_ack_missing)`、`bad_api_key`、`bad_endpoint`、`no_guilds` 等警告，代表功能沒有開起來，依代碼修正對應的環境變數即可。

## 10. 連結風險（第二個用途）

伺服器裡的成員訊息會先被小吉內建的離線規則檢查是否像釣魚或惡意連結（規則表在 docs/ARCHITECTURE.md）。規則判定有風險時，擁有者會收到「釣魚或惡意連結」的安全警示；**只通知，不刪訊息、不禁言、不回覆**。Jev 在這裡只是第二意見，補規則漏掉的：

- 只有在規則**沒有**判定有風險、訊息含連結、`JEV_LINK_RISK=yes`（這個用途自己的同意開關，預設關）、`JEV_MODE` 不是 off、`JEV_POLICY_ACK=yes`、金鑰有效、而且該伺服器在 `JEV_GUILD_IDS` 名單內時才會問 Jev。缺少任何一項、設定不完整或伺服器不在名單內，**完全沒有網路呼叫**，只用規則。
- `JEV_MODE=shadow`：只在 log 記一行 `[JEV_SHADOW] kind=link verdict=safe|risky|error`，不改變任何結果，用來觀察 Jev 的判斷；`enforce`：Jev 判有風險時也發出警示（log 前綴 `[JEV_ENFORCE]`）。Jev 說安全、出錯、逾時、被限流或電路中斷，都當作沒判定，只剩規則的答案。
- 呼叫不會讓訊息處理等待：訊息事件的其他處理照常進行，Jev 的答案回來時才處理，錯誤全部吞掉；同時最多 2 個呼叫、每分鐘最多 30 次（與第 7 節相同），超過就當作沒判定。
- 同一個伺服器同一類別的警示每小時最多私訊一次（一小時內只累計次數），所以一波釣魚洪水只會讓擁有者收到一則私訊。

**隱私**：這個用途會把**含連結的成員訊息文字**送到 TypeSafe AI。送出前的去識別化與第 6 節相同（提及換成 `[mention]`、15 位以上的數字換成 `[id]`、密鑰與權杖樣式遮蔽、最多 1500 字），另外連結只保留網域、路徑與查詢參數的名稱：帳號密碼、片段（`#...`）與每個查詢參數的**值**都會被拿掉，不送使用者 ID、伺服器或頻道名稱。其他成員寫在訊息裡的文字（例如被引用的內容）仍會原樣送出。啟用前同樣要先更新隱私政策與條款，涵蓋「含連結的伺服器訊息會被選用的第三方服務分析」。兩個用途共用 `JEV_MODE`、`JEV_GUILD_IDS` 與金鑰，但連結風險另有自己的同意開關 `JEV_LINK_RISK=yes`：只開回覆第二意見時，成員訊息不會被送出；如果只想用內建規則，不要設 `JEV_LINK_RISK`。
